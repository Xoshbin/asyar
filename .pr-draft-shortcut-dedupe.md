Title: fix(shortcuts): stop orphaned duplicate-chord shortcuts piling up after cloud restores

## What changed

- `ShortcutsSyncProvider.applyItemUpsert` now enforces one holder per chord. On a collision the newer `createdAt` wins (larger `objectId` breaks ties, so every device picks the same winner). The loser is dropped and tombstoned explicitly, because change events are suppressed while a pull is applied.
- New `shortcutDedupe.ts` (ordering rule + `findChordLosers`) and `shortcutHeal.ts` (`healDuplicateChords`), run from `agentsManager.refresh()` once the live agent list is known. It prefers the row whose agent is live and removes the other rows on the same chord via `shortcutStore.remove`, so tombstones sync.
- The bundled Grammar Fix agent now has a fixed id (`GRAMMAR_FIX_AGENT_ID = "grammar-fix"`). The seed looks the agent up by id first, then by name, so renamed agents and pre-existing uuid-keyed installs are both matched.

## Why

Agents are not cloud-synced, but their hotkeys are. After a local reset, onboarding re-seeded Grammar Fix with a new uuid and registered the chord under `cmd_agents_dyn_<new uuid>`. The cloud pull then re-added every old row via `shortcutStore.add`, which has no chord check. A dev DB ended up with 14 rows on `Super+Shift+L`, which also caused the startup freeze fixed in the previous commit.

## Reviewer notes

- The heal only removes duplicate-chord losers. A unique-chord row is never removed even if its agent id looks dead, because agent ids are per device and the row may belong to another device's live agent. Apps and commands not yet loaded at startup are likewise untouched.
- Not changed: `applyImport` (manual import), agent sync itself (would send prompts and model ids off-device), user-created agents (still uuid ids).
- Existing dead rows on a unique chord are left in place.

## Tests

- New: provider upsert collision tests (incl. a 12-stale-rows restore regression), `shortcutDedupe`, `shortcutHeal`, and two Rust seed tests (stable id, rename-then-reseed).
- `pnpm check:ci` passed before the final seed-lookup tweak. After it, `cargo test --workspace` and `cargo clippy -D warnings` passed. Please re-run `pnpm check:ci` before pushing.
